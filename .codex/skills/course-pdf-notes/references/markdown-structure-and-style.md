# Markdown 结构与版式

## 标题与语言

- 默认中文。必要的专业术语首次写作“中文（English）”，后文统一使用中文；课件已有稳定中英文对照时沿用其译法，避免为同一术语混用译名。代码、变量、函数、命令、公式符号、文件名和不可直译缩写保留原样。
- 课件有章节号时使用 `# 第 N 章：主题`，主要模块用 `## N.1`，子模块用 `### N.1.1`；没有章节号才从 `1`、`1.1` 开始。
- 标题应短且功能明确，例如“定态方程的推导”。不在开头添加“课程名｜”、覆盖范围或本节目标，除非用户要求。
- 空章节不保留；章节小结不是默认组件，只在课件明确给出或确实提供非重复统摄关系时保留。

## 知识块与信息层级

本仓库的 `.obsidian/snippets/course-note-layout.css` 管理课程笔记的提示块。不要新增 CSS 类型或在 Markdown 内写行内样式。

- 用无标题 `> [!knowledge]` 放可直接复习的定义、规则、条件、最终公式、结论、方法和知识性表格。相邻且同属一个知识点的内容合在同一块；表格每行保留 `>`。
- 推导过程、过渡语和常规代数不塞进知识块。例题、作业和待处理清单不能放进 knowledge 块。
- knowledge 块内小标题写成 `==🔴小标题==，小标题需要有总结意义，一个knowledge 块内一般有多个小标题`。`==黄色高亮==` 只标术语、符号、或专有名词；完整判断和因果结论用 `**加粗**`，不要把整段同时高亮或加粗。
- 按语义排版：真正独立的要点并列；“概念 → 定义/前提/组成”“步骤 → 子步骤”“结论 → 条件/例外”使用 tab 缩进的嵌套列表。不要为凑格式制造无归属的层级。
- 可用的其他块仅限：`[!note] 待插图`、`[!abstract] 本节小结`、`[!info] 主动补充`、`[!tip] 关键提示`、`[!warning] 易错点`。knowledge 的标题栏和图标由 CSS 隐藏，其他块保留中文可见标题。简单提示优先写成正文“注意：”；课件外的例题外说明必须用 `[!info] 主动补充`。

## 正文、公式和表格

- 正文从行首开始，段落间只留一个空行。禁止用全角空格、`&emsp;` 或行首空格模拟缩进；行首四个普通空格会变成代码块。例题标题、正文、图片和提示块之间也用一个空行分隔。
- 公式优先行内 `$...$`。三行以上连续推导、超宽式或需强调的结论才使用独立 `$$`；独立公式紧贴其引导句和解释，不以额外空行制造留白。符号首次出现时定义，并在结论附近写适用条件。
- 结构简单且可准确转写的源表格用 Markdown 表格；复杂表格或无法可靠转写的公式图片按图像规则处理。表格公式中的竖线改写为 `\lvert x\rvert` 或 `\|`，再检查每行列数一致。
- 两个及以上对象、条件、方法、参数或结论需要比较时，优先用表格、对比块或编号流程；这不能删去前提、例外、单位或关键推导。

## 统一风格请求

当用户要求“按当前笔记风格”“统一成相同样式”或“按统一标准修改”或者“按照skill要求”时，除上述规则外遵循：

- 由内容密度、图像数量决定 knowledge 块粒度。多个独立图或很长内容可拆块；短且紧密相关的内容可同块。
- 课件原图确能呈现结构或过程时，图片紧贴对应红色小标题和说明；装饰图、重复公式不嵌入。
- 每个关键公式至少说明量或系数含义、公式表达的关系及使用前提。不得只留公式或结论而丢掉课件解释。
- 并列结论使用列表或表格；删除“首次英文”和“页码”这类不服务复习的表格列。
- 需要集中复述 `boxed` 结果时，可用 `> [!knowledge] **最终导出：**`。
